# ADR-0003 — Flyway owns the schema; hand-written Identity SQL

Date: 2026-10-26 · Status: Accepted

## Decision

Flyway is the **only** schema migration mechanism. EF Core migrations are
disabled (`Database.Migrate()` is never called; no migrations assembly). The
ASP.NET Core Identity schema is hand-written in
`database/sql/V001__identity_schema.sql` to match exactly what EF Core +
Npgsql expect for `IdentityUser<Guid>`/`IdentityRole<Guid>`:

- Quoted PascalCase identifiers (`"AspNetUsers"."Id"`) — EF Npgsql quotes
  identifiers by default, so the SQL must match.
- `uuid` keys, `character varying(256)` for UserName/Email/Normalized*,
  `text` for hashes/stamps, `timestamptz` for `LockoutEnd`,
  `integer GENERATED BY DEFAULT AS IDENTITY` for claim ids.
- Custom columns `DisplayName`, `CreatedAtUtc`, `UpdatedAtUtc` mapped in
  `AppDbContext`.

An integration test creates a user through `UserManager` against the Flyway-
migrated schema and reads it back, proving the contract holds. If the Identity
package is ever upgraded, that test fails first if the schema drifts.

Naming: Identity tables keep EF's quoted PascalCase defaults; all
application tables use unquoted lowercase snake_case. Mixed but each area
internally consistent; Dapper SQL for Identity tables quotes explicitly.
